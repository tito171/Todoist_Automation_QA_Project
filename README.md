# 📝 Todoist Automation QA Project

Проект по автоматическому тестированию веб-приложения Todoist методом «черного ящика». Включает в себя проверку сложной бизнес-логики (сортировка, группировка, NLP-распознавание дат) с применением архитектурных паттернов проектирования и гибридным подходом (UI + API).

---

## 🛠️ Стек технологий и инструменты

* **Тест-раннер и плагины:** `pytest`, `pytest-order`
* **UI-тестирование:** `Selenium WebDriver`
* **API-взаимодействие:** `httpx`
* **Работа с данными:** `pandas`, `openpyxl`, `json`
* **Управление конфигурацией:** `os`, `python-dotenv`
* **Автоматизация задач (Таск-раннер):** `taskipy`
* **Отчетность:** `Allure Report`

## 🧠 Архитектура проекта

### 1. Паттерн Page Object Model (POM) и декомпозиция

Для управления веб-элементами и действиями на страницах используется паттерн **POM**. Чтобы избежать разрастания классов, самый объемный класс главной страницы был декомпозирован на изолированные компоненты:

* **`BasePage`** — содержит базовые методы взаимодействия с элементами (ожидания, клики, ввод текста).
* **`LoginPage`** — инкапсулирует логику авторизации.
* **`MainPage`** — отвечает за сбор «сырых» данных с интерфейса и их первичное преобразование. Включает в себя специализированные вложенные классы-компоненты:
  * **`SortingComponent`** — управление элементами и логикой интерфейса сортировки/группировки.
  * **`NLPInputComponent`** — взаимодействие с умным полем ввода задач.

### 2. Тестирование сортировки и группировки задач (Паттерны Strategy + Chain of Responsibility)

Реализованы тесты для проверки отображения списка задач при различных настройках сортировки и группировки.
Бизнес-логика проверки собранных с UI списков задач была вынесена в `tests/helpers.py` и завязана на поведенческих паттернах проектирования:

* **Стратегия (Strategy):** Разделяет алгоритмы проверки на независимые классы. Используются отдельные стратегии для валидации **группировки** задач и стратегии для **сортировки**. Это позволяет динамически подменять правила валидации в зависимости от тест-кейса.
* **Цепочка обязанностей (Chain of Responsibility):** Применяется для реализации комплексной **каскадной сортировки** Todoist. Так как приложение имеет строгие вложенные правила ранжирования, цепочка проверяет условия последовательно:
  * *Звено 1:* Проверяет сортировку по основному критерию (например, по **Сроку**). Если сроки равны, передает управление дальше.
  * *Звено 2:* Проверяет сортировку по **Приоритету** (строго по убыванию). Если приоритеты равны, передает управление дальше.
  * *Звено 3:* Финально проверяет сортировку по **Дате создания** (строго по возрастанию).

### 3. Тестирование NLP (Распознавание дат) и управление временем

Реализованы тесты для проверки «умного» ввода Todoist (NLP-распознавание дат и повторяющихся сроков, например: *"Каждый вторник в 15:00"*).

* **Смена времени:** Написан специальный метод `mock_browser_time` в файле `helpers/`, который подменяет браузерное время на заданную тестовую дату `GLOBAL_TEST_DATE`. Это позволяет изолировать тесты от текущего системного времени и гарантирует стабильность проверок.

### 4. API-Preconditions

Для ускорения UI-тестов создание тестовых задач выполняется через API-запросы в `tests/conftest.py` с помощью библиотеки `httpx` перед запуском теста сортировки.

### 5. Конфигурация и безопасность

Все настройки изолированы в файле `config`:

* Пути к тестовым данным (файлы Excel с тестовыми данными).
* Глобальные переменные и базовые URL для разных окружений.
* **Безопасность:** Чувствительные данные (учетные записи для авторизации и API токен) вынесены в файл `.env` и не попадают в систему контроля версий.

### 6. Оптимизация скорости тестов

Для исключения временных затрат на чтение и парсинг файлов Excel (`.xlsx`) во время выполнения UI-сценариев реализован механизм кэширования данных:

* Скрипт **`generate_test_data.py`** один раз вручную запускается перед тестированием, считывает таблицы через `pandas`/`openpyxl` и автоматически генерирует чистый Python-файл **`test_data_store.py`**. Повторный запуск скрипта требуется только для актуализации данных.
* Тесты импортируют уже готовые структуры (списки словарей `LIST_OF_TASKS`, `TESTS_RECURRING_CALENDAR`, `TESTS_DATA_AND_TIME`, `TESTS_SORTING_AND_GROUPNG`), что исключает повторное чтение с диска и существенно ускоряет прогон.

```text
├── docs/                                           # Папка с отчетом Allure о прохождении тестов

│   ├── login_page.py                               # Класс страницы авторизации

├── test_data/                                      # Файлы с тестовыми данными и списками задач
│   ├── list_of_tasks.xlsx                          # Списки задач для отправки через API
│   ├── test_data_store.py                          # Сгенерированный кэш данных в виде готовых Python-структур (списков/словарей)
│   ├── tests_date_and_time.xlsx                    # Данные для проверки дат
│   ├── tests_recurring_calendar.xlsx               # Данные для проверки повторяющихся сроков
│   └── tests_sorting_and_grouping.xlsx             # Данные для проверки сортировки/группировки
├── tests/                                          # Директория с тестами и фикстурами
│   ├── conftest.py                                 # Фикстуры (инициализация driver, авторизация, создание задач по API через httpx)
│   ├── helpers.py                                  # Логика проверок (Стратегии, Цепочка обязанностей, скрипт для установки времени в браузере)
│   ├── test_nlp_recognition.py                     # Тесты NLP распознавания дат
│   └── test_validate_ordering_and_grouping.py      # Тесты сортировки и группировки задач
├── .env                                            # Локальные учетные данные для авторизации (скрыт в .gitignore)
├── .env.example                                    # Шаблон переменных окружения для других разработчиков
├── .gitignore                                      # Исключение системных файлов, кэша и .env из Git
├── config.py                                       # Глобальная конфигурация (пути к Excel файлам, URL, переменные)
├── generate_test_data.py                           # Скрипт для генерации/подготовки тестовых данных (парсит Excel через pandas/openpyxl и перезаписывает файл test_data_store.py)
├── pyproject.toml                                  # Конфигурация таск-раннера taskipy с командой автоматизации полного цикла генерации отчетов
├── pytest.ini                                      # Базовые настройки тест-раннера pytest (включая поддержку кириллицы в параметризованных тестах)
├── README.md                                       # Документация проекта
└── requirements.txt                                # Список зависимостей (selenium, pytest, httpx, pandas и др.)
```

## 🚀 Локальный запуск проекта

### 1. Клонирование репозитория

Откройте терминал, перейдите в папку, где хотите сохранить проект, и выполните:

```bash
git clone https://github.com/tito171/Todoist_Automation_QA_Project.git
cd Todoist_Automation_QA_Project
```

### 2. Создание и активация виртуального окружения

Чтобы изолировать зависимости проекта от глобальной системы выполните команды:

* **На Windows:**
  ```bash
  python -m venv .venv
  .venv\Scripts\activate
  ```
* **На macOS / Linux:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

В корне проекта создайте файл `.env` на основе шаблона `.env.example` и укажите ваши учетные данные для авторизации в Todoist:

```env
TODOIST_EMAIL=your_email_here@example.com
TODOIST_PASSWORD=your_password_here
TD_API_TOKEN=your_API_token_here
```

### 5. Запуск тестов и генерация отчета

Для запуска полной сборки (очистка прошлых результатов, запуск тестов, сборка отчета и открытие его в браузере) выполните команду:

```bash
task report
```

## ⚙️ Модификация тестовых данных (Кодогенерация)

Если вам необходимо изменить тестовые сценарии (добавить новые строки для NLP-ввода, обновить списки задач или правила группировки):

1. Внесите изменения в соответствующие Excel-файлы внутри папки `test_data/`.
2. Запустите скрипт генерации данных:
   ```bash
   python generate_test_data.py
   ```

Скрипт автоматически перепишет файл `test_data_store.py`, преобразовав таблицы в быстрые Python-структуры, и новые кейсы сразу подтянутся в тесты.
